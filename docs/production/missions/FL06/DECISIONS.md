# FL06 Decisions

- **D01 — Pinned Hermes runtime**: Target `NousResearch/hermes-agent` `v0.23.4` (`8fc0374447313e276f6b9a2764bfc750190c966a`) API Server (`/v1/runs`, `/v1/runs/{id}`, `/v1/runs/{id}/events`, `/v1/runs/{id}/stop`, `/v1/capabilities`, `/v1/toolsets`, `/health/detailed`). Autonomous memory (`memory_enabled: false`, `user_profile_enabled: false`) and fallback routing (`fallback_providers: []`) are disabled; `delegation` uses `max_spawn_depth: 1`, `orchestrator_enabled: false`, `max_concurrent_children: 3`, `auto_resume: false`, `gateway_mode: inline`.
- **D02 — Preventive enforcement & honest delegation gate**: Authoritative budget, child-depth, child-concurrency, role-policy, and tenant/session/consent enforcement live in VAARG PostgreSQL + `ToolBroker`. A native Hermes `v0.23.4` plugin (`vaarg-confinement`) provides pre-LLM reservation, post-LLM usage reconciliation, child-session registration, and authenticated tool forwarding; if preventive hook attestation is absent, unrestricted delegation is disabled with an explicit capability limitation (`DISABLED_CAPABILITY_LIMITATION`), and unverified child sessions only receive the safe read capability intersection.
- **D03 — Direct providers only**: Only direct `gemini` (`Gemini API`) and `deepseek` (`DeepSeek API`) policies with `allowImplicitFallback: false` and `pricing.verified: true` are accepted; OpenRouter, Nous Portal, `auto`, and zero/unverified pricing are rejected fail-closed.
- **D04 — Hatchet SDK `1.49.1` & PostgreSQL authority**: `@hatchet-dev/typescript-sdk@1.49.1` executes registered background workflows (`vaarg.catalog.sync`, `vaarg.embeddings.refresh`, `vaarg.experience.retention_cleanup`), while PostgreSQL `workflow_executions` holds durable business submission state and handles `submission_unknown` without blind duplicate dispatch. Future FL07–FL11 workflow contracts are typed but refused with `WORKFLOW_NOT_IMPLEMENTED`.
