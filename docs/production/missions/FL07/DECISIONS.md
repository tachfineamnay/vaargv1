# FL07 Decisions

- **D01 — Official AG-UI SDK pins**: Installed exact `@ag-ui/core@1.0.5` and `@ag-ui/encoder@1.0.5` (`peerDependencies: { zod: '^3.25.18 || ^4.0.0' }`, compatible with workspace `zod@4.6.7`).
- **D02 — Official A2UI 1.0 wire schemas without preview 0.x renderer**: `@a2ui/react@0.16.1` is a `0.x` preview package targeting pre-1.0 drafts with a conflicting `zod@^3.25.76` peer dependency and `markdown-it`. Per PRD §2 and FL07 T04–T06, VAARG implements canonical A2UI `1.0` wire schemas (`https://a2ui.org/specification/v1_0/agent_to_renderer.json`, `renderer_to_agent.json`, `common_types.json`, `catalog_definition.json`) with strict Zod 4 server+client validators (`validateA2UiMessage`, `validateA2UiSurfaceBatch`, `resolveA2UiBoundValue`) and direct typed React 19 registry adapters (`A2UiSurfaceRenderer`) over existing FL04/FL05 VAARG storefront components, disabling `callRendererFunction` / `callAgentFunction` / `@call` arbitrary execution fail-closed.
- **D03 — Namespaced A2UI-over-AG-UI extension**: Validated A2UI `1.0` messages (`createSurface`, `updateComponents`, `updateDataModel`, `deleteSurface`) and synchronization signals travel inside AG-UI `EventType.CUSTOM` events with explicit versioned names (`vaarg.a2ui.v1.message`, `vaarg.context.v1.sync`, `vaarg.run.v1.resync_required`).
- **D04 — Out-of-band cryptographic confinement attestation**: Because Hermes `v0.23.4` (`run_server.py`) does not forward Python plugin HTTP headers on OpenAI-compatible responses, `vaarg-confinement` `1.1.0` signs canonical runtime attestation payloads with `HMAC-SHA256` (`VAARG_BRIDGE_SECRET`) and posts to `/internal/v1/hermes/runtime-attest`. `HermesAgentAdapter` checks `ConfinementAttestationRegistry` before issuing any `preventiveHooksVerified: true` bridge ticket.
- **D05 — Durable per-run PostgreSQL AG-UI stream log (`0015_fl07_agentic_surfaces_and_streams.sql`)**: Forward migration `0015` adds `agent_run_stream_events` (`UNIQUE (store_id, run_id, event_seq)`) with `FORCE ROW LEVEL SECURITY` and `vaarg_app` grants, plus `workflow_executions` status `continuation_required`. SSE clients reconnect with `<runId>:<eventSeq>` via `Last-Event-ID`; pruned cursors receive `vaarg.run.v1.resync_required` + fresh `STATE_SNAPSHOT`.
- **D06 — Constrained unbuffered `node:http` SSE BFF**: Node `undici` strips custom `Host` headers needed for VAARG multi-tenant host resolution. `apps/web/src/lib/transport.ts` (`openUpstreamSse`) uses `node:http`/`node:https` with `ReadableStream` chunk pass-through, forwarding only `vaarg_visitor_session` and `Last-Event-ID` while enforcing same-origin CSRF on all `POST` BFF routes.
