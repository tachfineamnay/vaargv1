# P02B operational boundary

- Provision a dedicated restricted runtime login granted `vaarg_app`; migration 0007 turns `vaarg_app` itself into a passwordless NOLOGIN role at PostgreSQL cluster scope. Assess other databases before any authorized migration. Migrations 0008 and 0009 add import leases and per-job receipts; do not edit 0002.
- Provide `STOREFRONT_BINDINGS_JSON` from trusted operator configuration. Each entry binds an exact lower-case storefront host to a store UUID, country, language, expected currency, Shopify `.myshopify.com` domain, secret environment-variable name, and optional explicitly authorized metafield identifiers. Separate secret injection supplies the token; never put its value into the JSON or logs. Duplicate or conflicting bindings fail startup. Verified domain ownership and trusted proxy/TLS configuration are operational prerequisites, not proven by parsing a Host header. Reverse proxies must preserve the authorized public Host and prevent direct untrusted access to internal services.
- Public `/catalog/products`, `/catalog/products/:handle`, `/catalog/collections`, `/catalog/collections/:handle` resolve only mapped hosts; `storeId` query overrides are rejected. Responses are no-store and disclose freshness; Shopify remains authoritative for current commerce facts. An absent binding/token is NOT_CONFIGURED; missing, ongoing, stale and fresh projections remain explicit.
- `/catalog/merchant/session` requires HTTPS Origin matching the configured host, rate-limits attempts through Valkey, and returns a bearer token in a no-store response. `/catalog/merchant/logout` revokes it. `/catalog/sync`, `/catalog/sync/step` and `/catalog/sync/delegation` revalidate scoped merchant membership; only owner/marketing roles can operate. TLS and secure credential storage at clients remain deployment requirements.
- Set the same strong `CATALOG_JOB_SIGNING_SECRET` in API and worker. Delegation creates an expiring signed store/user/action/job ticket, without exposing a bearer token in a durable payload; the worker rechecks active membership and job receipts prevent completed job replays advancing a second page. The endpoint returns a ticket and does not enqueue it. A future Hatchet adapter must safely transport tickets, avoid logging them and handle expiration; no Hatchet consumer is implemented or certified.
- The one-page CLI uses `CATALOG_HOST`, `CATALOG_ACTION` (`start`, `step`, `status`), the same bindings and secret variables, `DATABASE_URL` and `VALKEY_URL`. Every actual provider request uses per-store Valkey pacing and fails closed if Valkey is unavailable. Interrupted or expired leases can be retried; no DB row lock is held during provider requests.
- `SHOPIFY_REAL_TEST=1` is opt-in and read-only, only for an authorized test store with explicitly supplied credentials. The source tests here use synthetic Shopify responses; no claim of live provider validation, public launch, deployment or full P02 certification follows.
